# V3.6 multipath optimization checkpoint

Branch: `v3.6-multipath-optimization`

Known-good base: `93f5fbe18ff264a80301a97a605a9b4d2227f7ce` (`origin/v3.5-coarse-occlusion-shadow-cache`)

V3.6 preserves the complete generated V3.5 source chain and promotes only the three runtime optimizations supported by prior A/B results.

## Normal performance profile

`[V3] v3.6 performance profile = true` is enabled by default and makes these effective even when an older user configuration contains legacy false values:

- RAM cache Overdrive with Balanced preload.
- V3.3 Lua idle-timer fast path.
- V3.5 coarse paged-object and groundcover MSOC.

Each optimization has a separate V3.6 disable setting. Setting the profile false restores legacy per-setting behavior. Always-on correctness/safety fixes remain present in every mode.

## New bounded runtime experiment

- The asynchronous GPU pass profiler uses a 16-slot timestamp-query ring per pass and GL context. It tests `GL_QUERY_RESULT_AVAILABLE` before reading results, records query latency/drops, and never calls `glFinish`.
- Timed work includes the main camera, individual shadow cascades, water reflection/refraction, the post-processing composite, and individual post-processing passes. Existing OSG asynchronous draw timing remains the whole-frame reference.
- Far-cascade caster pruning uses OSG projected-size culling only on the farthest shadow camera. The default threshold is zero, so upstream shadow-caster behavior is unchanged unless the experiment is selected.
- Shadow telemetry records effective shadow distance, far resolution/divisor, and the active far-caster pixel threshold.

## New attribution

- Lua `addScript()` attribution separates cached chunk load, environment construction, common/container packages, require setup, nested module load, exclusive script-body time, handler extraction, and interface registration without changing Lua ordering or the worker barrier.
- Controller attribution separates keyframe lookup, node-map lookup, per-instance controller clone/type work, and controller-source assignment. Mutable controller state is not shared.
- Source-residency attribution records the largest cached images, estimated source bytes, dimensions/mips/compression, reference count, cache-entry count, and last-use time. It does not claim exact driver allocation and performs no eviction.
- Static-batching attribution measures repeated ObjectPaging templates and exact drawable/vertex topology before and after OpenMW's existing adaptive merge optimizer.
- Coarse-MSOC telemetry now estimates paged children and groundcover instances skipped by successful whole-group rejection.

## Unified launcher choices

- 24: true custom runtime baseline (profile off, normal RAM cache, V3 runtime experiments off).
- 25: normal V3.6 profile.
- 26: normal profile plus GPU pass profiler.
- 27: far-caster pruning isolated.

- 29: deep hitch/residency/static-batching attribution only.

V3.6 choices support 4096, 6144, and 8192 shadow-distance tests. Shadow choices also support far-cascade divisors 1, 2, and 4; divisor 1 is recommended, while divisor 4 remains a known flicker-risk comparison. Every run records CI identity, commit, executable SHA256, experiment name, effective settings, and telemetry, then restores the original `settings.cfg`.

## Deliberately deferred

- A true static/dynamic far-shadow split needs a second depth layer, RTT pass, texture bindings, and shader composition. The ineffective whole-far reuse design was not extended or relabeled as a static cache.
- Groundcover already uses hardware instancing. General ObjectPaging instancing needs compatible per-instance shader attributes and must be justified by the new topology telemetry before replacing the merge path.
- Foliage depth prepass needs a dedicated alpha-test-safe render path with identical discard semantics. No generic blended content is modified.
- Higher-level vegetation/world-region coarse groups need ownership and bounds in the paging/quadtree layers; V3.6 first quantifies the work skipped by the proven chunk level.
- Residency remains observational until visible/recent resource ownership and upload/release churn can be measured safely. No noisy NVML-driven eviction is used.

## Generated-source validation

The generator keeps V3.6 in independent `tools/v3/apply_v36_*.py` layers. Final packaging intent-adds generated new headers before creating `V3-applied-source.patch`, so the snapshot contains every source file compiled by CI. Local isolated generation, `git diff --check`, required-marker checks, the explicit no-`glFinish` guard, and PowerShell parser validation must pass before the remote preflight/full build.
