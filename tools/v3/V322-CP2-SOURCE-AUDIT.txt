Design objective
----------------
CP2 is intentionally innovative rather than conservative, but every mechanism is runtime-switchable in one executable and the known control remains available. CP2 targets occluder efficiency: make the fixed MSOC raster budget buy more useful depth coverage without changing ObjectPaging topology, child traversal order, PBR/shadow/FBFP semantics, or actual building visibility.

Innovation ladder
-----------------
Mode136: exact CP1 candidate/control; CP2 off.
Mode137: same 400-radius occluder population, but eligible unpaged building proxies consume the existing triangle budget front-to-back rather than arbitrary child order.
Mode138: same 400-radius population, utility-ranked by approximate projected coverage per raster triangle; near-distance tie break.
Mode139: Mode138 plus clean 300-radius eligibility. Proxy detail remains referenced to 400 radius, so lowering eligibility does not increase mesh resolution/triangle complexity for the already-eligible 400+ population. Distance remains 6144; triangle cap remains 30000.
Mode140: Mode139 plus redundant-raster suppression. A candidate that is already fully hidden by terrain or a previously rasterized ranked occluder can skip only its rasterization. The building itself has already traversed and is never culled by this optimization.

Semantic invariants
-------------------
- Pass-1 child traversal remains in original scenegraph order.
- CP2 does not reorder draw traversal or modify render bins/state.
- Cell terrain-only rejection remains unchanged.
- Door skipOcclusion handling remains unchanged.
- Camera-inside occluder exclusion remains unchanged.
- Large/paged-object path remains unchanged.
- Candidate visibility admission still requires terrain-only visibility before ranking.
- Global building triangle cap remains authoritative.
- Mode140 full-buffer test is used only to suppress redundant proxy raster work, never to suppress child traversal.
- CP2 adds no scenegraph UserDataContainer/DummyObject metadata and does not touch ObjectPaging.

Rejected-history boundary
-------------------------
The historical broad 250-radius / 8192-distance / 45000-triangle MSOC configuration remains rejected and is not revived. The aggressive branch is instead a clean 300-radius test with the existing 6144 distance and 30000 cap, combined with ranking and redundant-work suppression.

Build discipline
----------------
CP2 source/tooling is committed without [full-build]. The CP2 workflow first applies the complete generated V3.21 final stack + CP1 + CP2 from a clean checkout, compile-checks all Python generators, validates CP1 inheritance and CP2 mode/control markers, forbids ObjectPaging targets, runs git diff --check, parses the generated PowerShell launcher, and uploads the exact generated source patch for manual inspection. Windows/MSVC is authorized only by a later explicit [full-build] commit after that preflight and manual generated-source audit pass.
