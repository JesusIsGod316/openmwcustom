## Requested classification

1. **Important bug/crash fixes.** The BSShader TexMat fix prevents invalid
   shader permutations and is integrated. The auto-calculated spell-list work
   fixes official issue #9273 and remains a candidate. The refraction rewrite
   closes seven graphics/water/fog issues, but its large renderer footprint
   makes it unsuitable for an opportunistic V3.2 import.

2. **Performance improvements.** Removing the refraction RTT should reduce
   render-target work and related bandwidth. Its branch also simplifies
   `drawClippedLeaf` and removes per-leaf pushes. The shadow topic improves
   settings/thread interactions and stops constantly recreating `ShadowData`
   for the debug HUD. These benefits are coupled to large renderer changes and
   are deferred as units, not extracted without their surrounding invariants.

3. **Renderer / OSG / graphics improvements.** The refraction RTT removal,
   water/fog/render-bin changes, in-game shadow controls, shadow-map rescaling,
   and BSShader fix are the main graphics delta. Only the isolated BSShader fix
   is integrated at this checkpoint.

4. **Resource loading / paging / streaming improvements.** No standalone
   official change in this delta justifies integration. Although the refraction
   branch touches `SceneManager`, it does so for graphics resources rather than
   replacing the V3 prepared-instance, paging, or streaming systems.

5. **Lua/runtime improvements.** Projectile on-hit handlers are a substantial
   new Lua/runtime feature. Auto-calculated spell-list handling is a gameplay
   runtime correction. Neither is required for the V3.2 performance checkpoint;
   the projectile topic also overlaps generated Lua-manager code.

6. **Threading/workqueue improvements.** The shadow topic contains narrower
   shadow-settings threading work. No general `WorkQueue` replacement or clear
   upstream supersession of the custom scheduler appears in this delta.

7. **Memory/cache improvements.** No standalone cache-management change is
   present. Refraction RTT removal may lower GPU allocation/bandwidth pressure,
   but it does not replace the custom RAM policy, prepared-instance cache,
   hibernation cache, or GPU-pressure telemetry.

8. **Windows/MSVC fixes.** The refraction topic contains `0548dd0305` (`fix
   windows builds`), and the shadow topic contains `7fc769d719` (`Fix C4244`).
   Both are coupled to their parent renderer features. They should be taken
   with those reviewed migrations rather than cherry-picked onto code that does
   not yet contain the triggering changes.

9. **Changes that overlap or conflict with custom systems.** Direct tracked
   overlap between the clean V3.2 checkpoint and official delta is:

   - `apps/openmw/CMakeLists.txt`
   - `apps/openmw/mwrender/renderingmanager.cpp`
   - `apps/openmw/mwrender/renderingmanager.hpp`
   - `files/settings-default.cfg`

   The more important generated-tree overlap is:

   - `apps/openmw/mwlua/luamanagerimp.cpp`
   - `apps/openmw/mwlua/luamanagerimp.hpp`
   - `apps/openmw/mwrender/renderingmanager.cpp`
   - `apps/openmw/mwrender/renderingmanager.hpp`
   - `components/resource/scenemanager.cpp`
   - `components/resource/scenemanager.hpp`
   - `components/sceneutil/mwshadowtechnique.cpp`
   - `components/shader/shadermanager.cpp`
   - `files/settings-default.cfg`

   These files cover transition handling, hibernation, prepared instances,
   scheduler/telemetry plumbing, occlusion/shadow behavior, and Lua safety.
   Future integration must compare against the fully generated tree, not only
   the sparse source-patch branch.

10. **Unrelated changes.** The generic integration-test runner and projectile
    feature do not justify integration into the current performance checkpoint.
    The auto-spell fix is useful but unrelated to V3.2 performance and is held
    for a separately validated correctness batch.
